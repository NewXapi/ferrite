# `tasks/` — 任务书

给 agent 的**工单**：一次性的、有明确验收标准的活儿。不是 skill（不含可复用能力）、
不是 playbook（不是常驻规则）——**做完即失效**。

## 什么时候用

- 维护者想让某个会话去做一件**具体的事**，但不想写成长 prompt（prompt 会随会话消失）。
- 任务需要跨会话传递（会话 A 派发、会话 B 执行，或子代理接单）。
- 任务有多个步骤 / 明确验收，值得落盘而不是口头说。

**不要**把长期规则写进这里（那属于 `playbook/` 或 `AGENTS.md`）。

## 任务书模板

```markdown
# <任务标题>

- 状态：todo | doing | done（做完请直接删文件或移到已归档位置）
- 所属 PR / 分支：<branch 或 PR 链接，没有就写「待创建」>
- 工作目录：/home/hathaway/projects/ferrite/.wt/<name>/（**全局绝对路径**）

## 做什么（Goal）

一句话说清要达成的结果。

## 在什么地方

| 层 | 文件 | 动作 |
|---|---|---|
| … | `path/to/file` | 新增 / 修改 / 删除 |

## 验收标准（done when）

- [ ] 可执行的判据（哪条命令跑通 / 哪个断言变绿 / 哪个 URL 返回什么）
- [ ] …

## 非目标（明确不做）

- ❌ …

## 备注（背景 / 参考）

- 相关 playbook 文档：`.agent/playbook/xxx.md`
- 相关代码位置 / 历史 PR
```

## 约定

- **工作目录必须写全局绝对路径**——子代理一律用它，禁止相对路径推导（见 `AGENTS.md` 的 worktree 硬规则）。
- 一个任务书 = 一个可验收的成果；太大就拆（子任务 ≤ 5 文件 / 单一主题）。
- 做完：勾掉验收项、在 PR comment 留证据，然后删除该任务书（或移进归档目录）。
  `tasks/` 里堆已完成的任务会稀释信噪比。
- 任务书不替代 PR body 的任务清单：**任务书是派发用的**，PR body 是登记用的。

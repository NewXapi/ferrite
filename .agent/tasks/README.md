# `.agent/tasks/` —— 任务书

这里放**一次性的工单**：让某个 agent 去做一件具体的、有验收标准的事。

跟其他东西的区别：

- **不是 skill**（`skills/`）：skill 是可复用的能力包，被工具自动加载；任务书是干完就丢的活。
- **不是 rules**（`rules/`）：rules 是长期规矩；任务书是这一次的活。

**做完就删掉**（或者移走）。这里堆着一堆已完成的任务会干扰注意力。

---

## 什么时候该写任务书

- 维护者想让某个会话做一件具体的事，但不想写一条长 prompt（prompt 会随会话消失）。
- 任务需要跨会话传递（这个会话派发，另一个会话执行，或者交给子代理）。
- 任务有多个步骤或明确的验收标准，值得写下来而不是口头说。

**不该写进来的**：长期规则（那属于 `rules/` 或 `AGENTS.md`）。

---

## 模板

```markdown
# <任务标题>

- 状态：todo | doing | done
- 分支：<分支名，还没建就写"待创建">
- 工作目录：/home/hathaway/projects/ferrite/.wt/<名字>/   ← 必须写全局绝对路径

## 要做什么

一句话说清楚要达成的结果。

## 改哪里

| 文件 | 做什么 |
|---|---|
| `完整/路径/到/文件` | 新增 / 修改 / 删除 |

## 怎么算做完

- [ ] 能执行的判据（哪条命令跑通 / 哪个测试变绿 / 哪个地址返回什么）
- [ ] ……

## 明确不做

- 不做什么（避免 agent 自己扩大范围）

## 背景

- 相关的规则文档：`.agent/rules/<文档>.md`
- 相关的代码位置 / 历史 PR
```

---

## 约定

- **工作目录必须写全局绝对路径**。子代理一律按这个路径工作，禁止自己推导相对路径
  （原因见 `AGENTS.md` 里 worktree 的创建规则）。
- 一份任务书对应一个可验收的成果。太大的就拆开——单个子任务不超过 5 个文件、单一主题。
- 做完之后：勾掉验收项，在 PR 评论里留下证据，然后删除这份任务书。
- 任务书不替代 PR 正文的任务清单：**任务书是派活用的，PR 正文是登记用的**。

# 任务书模板（填号派工单）

> **什么时候用**：主控要把一个子任务派给子代理（或自己执行）之前，复制本模板填满——
> 空号发出去 = 子代理在哪一 freeing 发挥。**怎么填**：所有 `<...>` 替换为真实值，
> 「怎么算做完」的 checkbox 就是验收项，一条都不能空。
> 完整流程见 `../manual/pr-dev-workflow.md`；七问口径见 `../../tasks/feature-dev-handbook.md`。

# <任务标题：一句话说清做什么>

- 状态：todo | doing | done
- 分支：<分支名，还没建就写「待创建」>
- 工作目录：/home/hathaway/projects/ferrite/.wt/<名字>/ ← **必须写全局绝对路径**
- 派给：<哪个会话 / 主控自己 / 子代理>

## 要做什么

一到三句话说清要达成的结果。不要写步骤，步骤在「怎么改」里。

## 改哪里

| 文件 | 做什么 |
|---|---|
| `完整/路径/到/文件` | 新增 / 修改 / 删除 |

## 怎么算做完

- [ ] 可执行的判据：哪条命令跑通 / 哪个测试变绿 / 哪个地址返回什么
- [ ] 带证据：贴命令输出，或在 PR 评论里留下记录
- [ ] ……

## 明确不做

- 列出容易被顺手做掉的相邻改动，防止 agent 自己扩大范围
- ……

## 背景

- 相关规则：`.agent/rules/<文档名>.md`
- 相关代码位置、历史 PR、之前的尝试和结论

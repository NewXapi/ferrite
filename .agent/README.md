# `.agent/` — agent 协作区

> 这里放**给 agent 看的文档**。为什么用 `.agent/` 而不是 `docs/`：`docs/` 是给人看的项目文档；
> 这里是 agent 的常驻说明书 + 任务书，跟着仓库走、跨会话共享（git 跟踪）。

## 目录约定

| 子目录 | 放什么 | 谁在读 |
|---|---|---|
| `playbook/` | **规则与流程文档**（四段式：问题 → 意图 → 情况 → 约束）。从 `AGENTS.md` 抽离的正文都在这里 | 任何会话按 `AGENTS.md` 的触发条件进来取 |
| `tasks/` | **任务书**（一次性的、有验收标准的活儿）。不是 skill、不是文档，是「让 agent 去做某件事」的工单 | 接单的会话；做完归档或删除 |
| `skills/` | **omp 项目 skill**（`<name>/SKILL.md`，由 omp 自动发现并注入）。⚠️ 目录形状是 omp 发现机制的契约，**不要放普通文档** | omp 自动加载 |

### 三者的区别（别混）

- **`skills/`**：能力包，工具自动发现、名字进系统提示；改动会影响每次会话的上下文。
- **`playbook/`**：规则/流程，**不自动加载**，靠 `AGENTS.md` 的指针按需读。放在这里 = 减少常驻上下文。
- **`tasks/`**：一次性工单，明确「做什么 / 验收是什么」。做完即失效。

## playbook 索引

| 文档 | 什么时候读（触发条件） |
|---|---|
| `pr-workflow.md` | 开 PR / 派子代理编排开发前（八阶段剧本 + 硬性门禁） |

| `gates.md` | 提交被拦 / `gh` 操作被 gate 拒 / 查 gate 规则 |
| `dev-env.md` | 起后端/数据库/前端，或前端报 500/404、构建卡死、dx 异常 |

## playbook 文档写法（四段式）

新增 playbook 文档时按这四段组织，AGENTS.md 里只留**触发条件**摘要：

1. **遇到什么问题**（含曾经踩过的坑）—— 症状 + 判据，便于对症检索
2. **维护者希望做什么事** —— 目标与期望做法
3. **可能的情况** —— 分支场景、步骤表、变体
4. **约束事项（简略）** —— 硬约束与红线

# `.agent/` 目录说明

这是给 agent 看的目录。跟 `docs/` 的区别：`docs/` 是给人看的项目文档；这里的东西是
**规则**和**任务书**，跟着仓库走、多个会话共享。

## 只有两个子目录

```text
.agent/
├── rules/     ← 要遵守的规矩（长期有效）
├── tasks/     ← 派发的活（一次性，做完就删）
└── skills/    ← 工具自动加载的技能包，不要往里放文档
```

### `rules/` —— 规矩

这里的文档不会自动加载。`AGENTS.md` 里每节都写了"什么时候读哪份文档"，
按那里的指引进来即可。**每份文档开头都写了"什么时候读"和"这份文档解决什么"。**

| 文档 | 什么时候读 |
|---|---|
| `.agent/rules/pr-workflow.md` | 要开 PR 干活，或要派子代理分担任务时（完整流程 + 硬性门禁） |
| `.agent/rules/testing-ci.md` | 要写测试、要跑测试、要看 CI 结果时（含三个"CI 绿了但没验东西"的坑） |
| `.agent/rules/gates.md` | 提交或推送被拦、创建 PR 被拒、要查检查规则时 |
| `.agent/rules/dev-env.md` | 要启动后端 / 数据库 / 前端，或前端报错、构建卡住时 |
| `.agent/rules/conventions.md` | 写前端界面、写 Rust 公共接口、调查或审查代码时 |

写新的 rules 文档时：开头写清楚"什么时候读"和"这份文档解决什么"，
然后按 **遇到什么问题 → 希望做什么 → 可能的情况 → 约束事项** 四段来写。

### `tasks/` —— 任务书

一次性的活。跟 skill 的区别：skill 是可复用的能力包（被工具自动加载），
任务书是"让某个 agent 去做某件事"的工单，做完就失效。

模板和约定见：`.agent/tasks/README.md`

### `skills/` —— 工具自动加载，不要动

`skills/` 下的目录结构是 omp 的发现机制要求的（只扫描 `各目录/SKILL.md`，不递归）。
往这里放普通文档不会被加载成技能，只会造成混乱。**普通文档放 `rules/` 或 `tasks/`。**
